Kali already has powerful tools. The point of WiFiScan is not to outperform
Aircrack-ng, NetworkManager or Wireshark. It is to make the steps between
them easier to understand and repeat.

A framework should connect tools into useful workflows, not turn every
command-line option into another checkbox.

## Start with a task

The new desktop interface has three tasks:

- **Passive inventory:** detect suitable adapters and listen without joining
  networks or enabling active reconnaissance.
- **Capture lab AP:** choose an authorized network from a dropdown, then
  capture it for 60 seconds. Its BSSID and channel are filled in for you.
- **Audit saved capture:** choose a capture and your own wordlist, identify
  the authorized BSSID, and run the offline Aircrack-ng workflow without
  needing a radio or administrator access.

The dropdown shows SSID, BSSID, channel and security, so two access points
with the same name are not confused. It starts with NetworkManager's cached
list. **Find networks (Wi-Fi scan)** explicitly requests a fresh scan on the
listening adapter. That discovery can send probe requests; the capture itself
does not inject traffic or associate with a network.

There is no repeated authorization checkbox in the GUI. Choosing a scoped
task and starting it confirms authorization; the backend still receives its
explicit authorization flag. This is not permission to test someone else's
network.

Adapter choices, manual target entry, capture duration and output location
remain under **Advanced settings**. They are escape hatches, not homework
before every run.

## Let the existing tools do their jobs

WiFiScan uses `iw` to inspect adapters and manage monitor mode, NetworkManager
to discover APs, Airodump-ng to capture, and TShark to inspect EAPOL frames.
Saved-capture audits use Aircrack-ng, with an optional Hashcat path available
through the CLI. Local vendor data adds context to inventory results.

The GUI runs as a normal user. PolicyKit prompts only for privileged radio
operations and their stop request. It checks inputs before asking for
elevation, shows backend errors, and keeps settings fixed while a job runs.

It also recommends a disconnected monitor-capable adapter instead of
sacrificing the radio carrying your connection. Each GUI run gets a separate
private output directory. Reports remain root-owned after radio work, and
**Copy results path** provides the exact location for reading them with sudo.

## Tested on real Kali hardware

The lab used a dedicated Kali machine, a Realtek RTL8812AU USB Wi-Fi adapter,
and an owned OpenWrt access point configured as an open test network.

The Debian package was built, installed and upgraded on that machine.
The installed GUI passed 27 Python tests under a virtual display, alongside
the shell regression suite. Coverage includes mode-specific forms, network
selection, validation, readable output, stop-error handling and a GUI-to-backend
offline workflow with a mocked audit tool.

Real cached lookup and a fresh discovery scan both found the lab AP with
the correct BSSID and channel. Live BSSID-filtered capture detected that AP,
exited successfully, restored the USB adapter to managed mode and preserved
the other adapter's connection. The desktop capture workflow was also
manually exercised during development.

Zero EAPOL frames on an open AP with no associated clients was expected.
This did **not** validate WPA2 handshake recovery or password auditing against
a real protected network. Those remain separate lab checks, not implied
successes. An open Wi-Fi link also does not mean HTTPS encryption disappears.

One useful hardware lesson: the USB adapter repeatedly disconnected before
being reconnected directly and settling. Check USB stability before assuming
the capture software or monitor-mode settings are broken.

## Try the framework

The tools have moved to the private
[Pentest Suite repository](https://git.scandinavianhacking.dedyn.io/The66Monkey/Pentest-suite).
With repository access, on Kali or Debian:

```bash
git clone https://git.scandinavianhacking.dedyn.io/The66Monkey/Pentest-suite.git
cd Pentest-suite/Kali
bash packaging/build_deb.sh
sudo apt install ./packaging/dist/wifiscan_1.1.1_all.deb
wifiscan-gui
```

Live workflows require two Wi-Fi adapters, one with monitor-mode support.
Start with your own isolated lab, and keep captures private.

The [WiFiScan documentation](https://git.scandinavianhacking.dedyn.io/The66Monkey/Pentest-suite/src/branch/main/Kali/README.md) covers the workflows,
CLI alternatives and remaining validation limits. The goal going forward
is the same: connect proven tools into a small number of understandable
tasks, with sane defaults rather than a wall of configuration.
